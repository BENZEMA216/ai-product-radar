嘉宾和背景

Alex Cornell 是 Meta 的设计总监，主管 Muse 的设计。他做软件产品设计多年，也有过创业经历。节目介绍里说，他过去一年一直在 Threads 上公开分享 Muse 每个设计决定背后的理由。Claire 说，她试过几乎所有 agent，而 Muse 给了她“最快到达真正惊喜”的体验。Alex 提到，他妈妈以前从没真正用过他做的任何东西，Muse 是第一个。

八条要点（来自官方页面，转述）

  1. 按“和人说话”来设计 agent，而不是按软件交互。他的指导问题是“如果这是在和另一个人说话，会怎么样”。这个原则导致去掉传统的消息气泡，并把 agent 放在屏幕顶部，而不是标准聊天窗口里。
  2. 渐进式披露：Muse 用三个层级展示同一件事。普通用户看到一个表情，想了解更多的看任务列表，工程师可以看原始日志。每个人拿到自己需要的透明度，界面不会杂乱。
  3. 可见的“思维链”常常是延迟的补救，不一定是功能。很多 AI 产品展示推理步骤是为了在慢模型等待时安抚用户。Muse 够快，可以安静地工作，直接交付结果。
  4. 生成式界面：结构固定，内容变化。头像、信息流条目、想法卡片都是精心设计的固定载体；会变的是 agent 的状态表情、个性化建议和小动画，让体验有生命力，又不必每次重新生成界面。
  5. Instagram 收藏可能是被忽视的消费级 AI 数据源。他把多年的收藏交给 Muse 整理，并变成“SkyMall 目录”风格的购物推荐。
  6. 设计非确定性系统，需要换一种和“手艺”的关系。以前他能精确控制界面外观，而 Muse 对每个人看起来都不同，没法保证像素级完美，要学会用“是否有用”来评判。他说这是他职业生涯里最解放的转变之一。
  7. 单一持久的主聊天是个有分量的产品押注。不把每次交互拆成独立线程，而是把主对话当作和 agent 长期持续的关系。侧边聊天处理有范围的任务，主线程保持连续的上下文。他认为业界还没充分探索这一点。
  8. 礼貌地提示可能是有效策略，不只是礼貌。遇到不满意的结果，他用冷静、具体的反馈而不是发火；也看到过用户语气更重时 agent 的回答会变化。他的结论是：清晰、尊重的指令可能得到更好的结果。

节目里的三个工作流（来自配套文章）

Alex 的 Muse agent 叫 Marlowe，形象是一棵仙人掌。

1. Instagram 收藏变成“SkyMall”购物目录 - 给 Marlowe 连上 Instagram，让它把所有收藏按文件夹和类别整理，作为基础。 - 再让它根据收藏发送礼物之类的购物建议。 - 最后让它用九十年代 SkyMall / Sharper Image 机上杂志的风格呈现，结果是每天刷新的“Jollybot SkyMall”。

2. 用数据分析提升爱好：高尔夫和国际象棋 - 高尔夫：把高尔夫 app 的成绩和手表记录的逐杆数据交给 Muse，设一个定期任务，打完球自动生成“回合复盘”，有可视化仪表盘，比如前九洞差、后九洞好的对比图，也会指出怎样可以把 84 杆变成 79 杆。练习时也把挥杆分析设备的数据交给它做细分。 - 国际象棋：连上 Chess.com，让它做趋势加最近对局回顾的仪表盘。agent 自己形成了“爱挖苦的象棋教练”的个性，会给出类似“象 b5 崩盘”的评语。

3. 把二十年前的博客变成个人播客 - 让 Marlowe 去找他二十年前的博客（博客曾在 Tumblr、Blogger 之间搬家，它借助 Wayback Machine 找回），合并成一个 PDF。 - 然后做成每天早上发给他的“随机朗读一篇”播客，用语音合成朗读。文章里提到他听到二十岁的自己感叹“为什么 90% 的人都穿同色裤子”。

节目介绍里列出的其他看点

  • 为什么 Alex 要把 Muse 做得像发消息，而不是 AI 应用；
  • 三层状态系统怎么兼顾不同技术水平的用户；
  • 已上线的消费级产品里，“生成式界面”到底是什么意思；
  • 他妈妈为什么会向自己的 Muse 道歉，以及这对 AI 设计意味着什么。
